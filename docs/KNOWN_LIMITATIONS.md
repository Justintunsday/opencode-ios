# Known limitations — OpenCode iOS (rootless, v1)

This list is deliberately honest. Every item is either a **documented fallback**
implemented in the port or a **known limitation observed on real hardware**.
"CI-green" does not override any of it. Target device: iPhone SE 2, iOS 16.1.1,
Dopamine rootless. **Current release `v2.2.5-ios.5` (SHA-256
`b23ed1fc6f99ab67c0882cfed5c990d941e99984e4ccbaa622e23bbd75f0f073`) is
DEVICE-VERIFIED — packaged acceptance PASS=14 / FAIL=0 plus packaged REPL PTY
acceptance and non-TTY guidance checks (2026-11-01). Previous releases
`v2.2.5-ios.3` (`8a625f75…`, PASS=14/0 + TUI-guidance PTY tests) and
`v2.2.5-ios.2` (`2f96fc18…`, PASS=14/0) are kept for traceability. Candidate
`v2.2.5-ios.4` is superseded/NOT device-verified.** Raw evidence:
[`DEVICE_TEST_RESULTS.md`](DEVICE_TEST_RESULTS.md).

| # | Limitation | Impact | Status |
| --- | --- | --- | --- |
| 1 | **No native PTY for interactive terminal panes.** Upstream `@opencode/pty`/`node-pty` has no iPhoneOS build; shell tool calls use pipe-based `child_process` fallback and spawn the rootless dash (`/var/jb/bin/sh`) through the launcher's `PATH` prepend. | No interactive TTY allocation for tool-invoked shells; TUI terminal panes degrade or are unavailable. Headless `opencode run` is the reliable mode (device-verified via the packaged launcher). | documented fallback |
| 2 | **The stable Node 22 release provides a line-based REPL (patch `0012`, turn-lifecycle fix `0013`, retry budget `0014`; DEVICE-VERIFIED in released `v2.2.5-ios.5`).** The full OpenTUI interface cannot run on the iPhoneOS Node 22.9 runtime: `@opentui/core` 0.8.0's Node binding requires **Node.js >= 26.4.0 with `--experimental-ffi` (`node:ffi`)** to load its native Zig core, and Node 22.9 has no `--experimental-ffi` (device-verified: `bad option: --experimental-ffi`). The **line-based REPL** (plain readline loop, streamed assistant text + tool activity, `/new`, `/exit`, `/help`, Ctrl-C cancels the current turn, session continuity) is what the stable Node 22 package starts in a TTY; `opencode mini` aliases it there. Patch `0013` recreates/re-resolves the server connection per turn (the first packaged candidate `v2.2.5-ios.4` failed agent turns by reusing a dead connection); patch `0014` gives each turn a 3-attempt budget with a fresh connection, 1 s spacing and a 300 ms first-turn warm-up, and a persistent failure returns cleanly to the prompt. **Occasional transport errors on the first attempt are expected** (intermittent iPhoneOS network/runtime flake — the same flake appears with headless `opencode run`): the REPL retries and the turn usually succeeds on retry. Non-TTY invocations (`opencode </dev/null`, scripts) print clean guidance and exit 1. The separate experimental node26test.4 package has a DEVICE-VERIFIED real full-screen TUI; see item 31. | Use the REPL interactively (NewTerm 3 / SSH TTY) or the headless `opencode run ...` interface; expect an occasional first-attempt transport error and retry. `--help`, `models`, `auth`, `session`, `debug` are also available. | stable Node 22 full TUI: unavailable; experimental Node 26 full TUI: DEVICE-VERIFIED (item 31); REPL: **DEVICE-VERIFIED** in packaged `v2.2.5-ios.5` (turn-1 first attempt, retried turn recovered on attempt 3, `/new`, `/exit` rc=0, shell-tool marker, non-TTY guidance rc=1) |
| 3 | **No native file watcher.** `@parcel/watcher` has no iPhoneOS build; watch-based features fall back to polling/backend fallbacks (device log: "watcher backend not supported", non-fatal; polling/other watchers still deliver file-change events). | Live reload/incremental watching may lag or not happen; re-run commands to observe changes. Large repositories are affected more. | documented fallback (device-observed) |
| 4 | **No `fff`/`ffi-rs` native modules.** Upstream ships an unavailable-proxy fallback for ffi; it is selected on iOS. Desktop native binaries are removed from the packaged assets (CI rejects stock bundles that still contain them). | Features requiring native FFI (and fff-backed search/UI helpers) are unavailable. Pure-JS and WASM paths can work because the final runtime enables WebAssembly, but wasm-backed optional components are not individually validated on device. | documented fallback |
| 5 | **Runtime variants: Node 22.9.0 v6 (stable), Node 18.20.4 (fallback), and Node 26.13.0 (experimental real TUI, item 31).** The `.deb` ships exactly one. The **node22 v6 runtime is DEVICE-VERIFIED for the released package** with the mandatory `--single-threaded` launcher flag (JIT/WASM/fetch/ICU/CLI matrix and mock-provider agent turn PASS); node18 remains the documented alternative (V8 10.2 memory model, sql.js sqlite shim, acceptance pending). Upstream OpenCode's Node build path normally targets an even newer Node version, so APIs added after the chosen line are missing (e.g. `module.registerHooks` on Node 18/22.9); the iOS prelude avoids them and the Vite bundle is patched. All three runtime variants are built with WASM+JIT+full-ICU. | Variant-specific behaviour must be taken into account when triaging; `package-report.json` records `variant`/`runtime_kind`. | node22 v6: DEVICE-VERIFIED (packaged PASS=14/0); node18: fallback, acceptance pending |
| 6 | **JIT + WebAssembly are required; iOS W^X handling is the hard part.** Node's built-in fetch/undici needs WebAssembly (wasm llhttp). JIT-less/WASM-disabled runtimes failed on device with `ReferenceError: WebAssembly is not defined`. The **node22 v6 runtime uses an mprotect RW⇄RX W^X model** (patch series `0004`/`0005`/`0006`; no MAP_JIT, no RWX) with the 2-key entitlement set, **device-verified when V8 runs single-threaded**. Without `--single-threaded`, JIT-heavy code SIGBUSes (signal 10/exit 138) because V8 background threads race the process-wide mprotect toggle; earlier v3/v4/v5 builds were device-incompatible and are superseded. The **node18 fallback** uses the V8 10.2 memory model that is device-proven. | The node22 launcher must always pass `--single-threaded`; removing it can SIGBUS. Node 18 remains available as a fallback with its own caveats. | DEVICE-VERIFIED for the released node22 v6 package with `--single-threaded` |
| 7 | **Entitlements are device-verified: the 2-key set.** The working minimal runtime entitlement set is exactly `platform-application` + `com.apple.private.security.no-sandbox` (device-verified inside the released package; old 4-key allow-jit sets without those keys were SIGKILLed, exit 137). All three runtime executables use this 2-key set; the v4 Node 22 experiment used a tentative 4-key set but that build was device-incompatible for memory-model reasons, not signing. The loader can SIGKILL on an unresolved extra entitlement. | If the runtime is killed at startup, repair/re-sign with the shipped `runtime/entitlements.xml` only; do not add other keys randomly. | device-verified (2-key set) |
| 8 | **No GUI/desktop application.** CLI only. | No menu-bar app, no GUI editor, no native window; use NewTerm 3 or SSH. | documented constraint |
| 9 | **Jailbreak required; rootless only.** Only `iphoneos-arm64` + `/var/jb` prefix (Dopamine-style) is packaged and validated. | Rootful jailbreaks, other prefixes (`/var/jb` absent) and non-arm64 devices are unsupported. | documented constraint |
| 10 | **Only iPhone SE 2 / iOS 16.1.1 is targeted.** No testing on other models/iOS versions. | Behaviour on other devices is untested; minimum iOS stated by the runtime is ≤ 16.1.1 (build target iOS 15.0). | unverified |
| 11 | **Sessions/config/data live in the user home** (`HOME=/var/jb/var/mobile` on this device, e.g. `~/.config/opencode`, `~/.local/share/opencode`). | They are user data: preserved across `dpkg -r`/`dpkg -P`; cleared only if the user manually deletes them. Backup/restore is the user's responsibility. | documented behaviour |
| 12 | **Auto-update disabled.** The CLI is managed by dpkg, not a self-updater. | Upgrades go through new `.deb` artifacts/`dpkg -i`; no in-app network updater. | documented fallback |
| 13 | **Memory limits / jetsam.** iPhone SE 2 has 3 GB RAM; a large session can be killed by the OS before V8 GC settles. | Launcher caps V8 old space at 1536 MiB by default; override with `OPENCODE_IOS_MAX_OLD_SPACE_MB`. Very large repositories may still fail. | documented mitigation |
| 14 | **No background execution/daemon.** iOS does not allow a jailbreak CLI to stay resident like a server. | `opencode serve`-style long-running workflows are not validated for background/headless persistence; run in a foreground terminal/SSH session. | unverified |
| 15 | **TLS/CA and corporate proxy behaviour** relies on iOS system trust; custom proxies, client certificates and interception are untested. | Network/auth failures may occur in managed environments. Basic device HTTPS/TLS was verified (200 response, curl works) but proxies remain untested. | unverified |
| 16 | **Package is unsigned for Cydia/Sileo repo distribution** (no repo metadata, no package-signing key). | Install the `.deb` manually or via Filza/local Sileo; `dpkg` may warn about unauthenticated local installs. | documented limitation |
| 17 | **Device verification is reported by maintainer/owner, not CI.** Hosted runners cannot execute iOS arm64 binaries. | The released package is DEVICE-VERIFIED (PASS=14/FAIL=0, 2026-11-01) with raw evidence in [`DEVICE_TEST_RESULTS.md`](DEVICE_TEST_RESULTS.md); CI reports keep the runner-scoped `UNVERIFIED ON DEVICE` wording by design. Other devices/iOS versions remain unverified. | device-verified for the released artifact; CI cannot verify devices |
| 18 | **No `/bin/sh`, `/bin/bash` or `/bin/zsh` on rootless iOS.** Rootless shells live under `/var/jb`; the launcher and packaged helper scripts use `#!/var/jb/bin/sh`, while `DEBIAN/postinst`-style scripts keep `#!/bin/sh` (handled by patched rootless `dpkg`, device-verified). | Scripts must not hardcode `/bin/sh`; user-run helpers should be invoked as `sh /var/jb/...` or with the rootless shebang. | documented constraint |
| 19 | **`git` is not bundled or hard-required.** The package declares `Recommends: git`, not `Depends`. | Git tool features need `sudo apt-get install -y git` (Procursus apt, device-verified git 2.39.1). `dpkg -i` works without it. | documented behaviour |
| 20 | **ICU/Intl build requirement.** The Node runtime must be built with `--with-intl=full-icu` (small-icu trims Intl data and `Intl.Segmenter` misbehaves; the CLI uses it, and a community small-ICU Node 18 runtime crashed `opencode --help` in `JSSegmenter::Create` on the target device). An early build used `--with-intl=none`: `Intl` was undefined and V8 rejected the Unicode property escapes used by the CLI bundle (`SyntaxError: Invalid regular expression: /[\p{Mark}\p{Control}...]/gu`), so the CLI could not start on device. | All three runtime variants are built full-ICU; the packaging CI rejects runtime artifacts whose manifest declares `--with-intl=none` or that omit the full-ICU declaration. | documented constraint (device-verified requirement; satisfied by the shipped runtimes) |
| 21 | **Node 18 sqlite uses a bundled sql.js (WebAssembly) shim.** `node:sqlite` does not exist on Node 18, so the Node 18 CLI bundle maps it to `assets/node18-sqlite/sql-wasm.{js,wasm}`. | Persistence is whole-file (no WAL): the database is written out as a file, and a hard crash can lose recent writes (~≤250 ms of writes per the shim design). Large sessions may be slower and use more memory than native sqlite. The released primary node22 variant uses native `node:sqlite` with WAL (device-verified). Close/quit the CLI cleanly before copying or backing up the database. | documented fallback (node18) |
| 22 | **Inspector / CPU profiling is a stub on Node 18.** `node:inspector` is not available on the cross-built Node 18 runtime, so CLI patch `0008` replaces it with a stub that reports unavailability instead of crashing. | `--inspect`, CPU profiles and heap snapshots are unavailable/best-effort on the node18 variant; debugging must use logs. | documented fallback |
| 23 | **`run --standalone` child-server start needed CLI patches.** Early device runs found `opencode run --standalone` could not start its child server; CLI patch `0009` fixed the direct-spawn path and patch `0010` forwards `--single-threaded` to spawned children. | Standalone mode is fixed and was exercised on device in the released package (`opencode run --standalone` mock-provider agent turn, shell tool executed). If a custom build lacks these patches, standalone mode may SIGBUS/fail. | fixed and DEVICE-VERIFIED in the released package |
| 24 | **The node18 CLI device evidence was gathered with a community Node 18 runtime, not the packaged one.** `--version`, `debug paths`, `debug config`, `models`, `session list` returned rc=0 and sql.js sqlite worked; `--help` crashed only because that reference runtime is small-ICU. | The packaged acceptance run (own full-ICU Node 18 runtime) is still required for the node18 fallback; node22 v6 is the primary path. | preliminary device evidence |
| 25 | **`TMPDIR` may be unset in device sessions.** Some SSH/NewTerm sessions do not export it; the CLI/sqlite need a writable temp dir. | Both launchers provide a `TMPDIR` fallback (`/var/jb/tmp`, `/var/jb/var/tmp`, `/tmp`) when unset; `device-smoke.sh` checks and reports it. | documented mitigation |
| 26 | **Node 22 v6 requires `--single-threaded` (V8 single-threaded platform).** The runtime toggles W^X process-wide with mprotect RW⇄RX; background V8 threads race the toggle and JIT-heavy code SIGBUSes without the flag (device-verified: default mode SIGBUS 138 on JIT loop/fetch, single-threaded PASS). | Removes V8 worker/background-compiler parallelism, so multi-threaded workloads are slower or serialized; the launcher always passes the flag and `device-smoke.sh`/validation assert its presence. ## Notes

- Items marked **documented fallback** are implemented choices in the port (the
  CLI behaves as described above); items marked **device-observed/unverified**
  reflect real-hardware evidence or remain unproven and are not claimed to work.
- **Device verification for the released artifact** is recorded in
  [`DEVICE_TEST_RESULTS.md`](DEVICE_TEST_RESULTS.md) (packaged acceptance
  PASS=14/FAIL=0, 2026-11-01) and condensed in
  [`VERIFICATION.md`](VERIFICATION.md) → *Device verification results*. Earlier
  bootstrap probes remain under *Interim device evidence* and are superseded.
- CI **rejects** packages whose runtime entitlements lack the device-verified
  minimal pair (`platform-application` + `com.apple.private.security.no-sandbox`),
  packages built from stock (non-iOS) CLI artifacts, runtime artifacts that are
  not full-ICU or that lack WebAssembly/JIT (or contain `--v8-options=--jitless`),
  variant/artifact mismatches (a node18 CLI bundle with a node22 runtime or vice
  versa), node22 launchers missing the mandatory `--single-threaded` flag, and —
  for the **node22 variant only** — JIT-enabled runtime manifests without an iOS
  W^X patch (`0004`/`0005`/`0006` family); those are hard failures, not warnings.
  The node18 variant intentionally does not require the Node-22-only W^X patches
  (V8 10.2 uses its own device-proven memory model).
- Package history: **node22 v6 is the released, DEVICE-VERIFIED primary path.**
  Current release `v2.2.5-ios.5` — `.deb` SHA-256
  `b23ed1fc6f99ab67c0882cfed5c990d941e99984e4ccbaa622e23bbd75f0f073`
  (package run `41292412240`; runtime `41273024931`; CLI `41291337297`, patch
  `0014`; packaged acceptance PASS=14/0 + REPL PTY acceptance + non-TTY guidance).
  Previous releases `v2.2.5-ios.3` (`.deb` SHA-256 `8a625f75…`, PASS=14/0 +
  PTY TUI-guidance tests) and `v2.2.5-ios.2` (`2f96fc18…`, PASS=14/0) are kept
  for traceability. Candidate `v2.2.5-ios.4` (`299ee574…`) is superseded / NOT
  device-verified (REPL agent turns failed) — do not publish. Do **not**
  rebuild/replace a released artifact without re-running device acceptance.
  Superseded node22 builds are not shippable: v1 intermediate (run `41185611403`;
  WASM-disabled), v3 (run `41202900005`; SIGBUS), v4 (run `41218342323`; SIGTRAP/
  `FatalOOM` at V8 code-range reservation), v5. **node18** remains a documented
  alternative fallback (CI-validated package `41291038144`, `.deb` `0be49c37…`;
  UNVERIFIED ON DEVICE, no primary acceptance requirement).
- Optional bundled `rg` (stretch `ios-ripgrep` artifact) is only used if the
  artifact was published; its absence is reported as `SKIP`, not as a failure of
  the package. The optional `libjitshim.dylib` (`ios-jit-shim` artifact) is
  likewise included only when published (node22 variant only) and is injected
  via `DYLD_INSERT_LIBRARIES` only when present; it is a jailbreak JIT W^X
  interposer, documented and audited in `package-report.json`.
- See [`VERIFICATION.md`](VERIFICATION.md) for the exact CI evidence classes and
  [`INSTALL.md`](INSTALL.md) for device troubleshooting.
